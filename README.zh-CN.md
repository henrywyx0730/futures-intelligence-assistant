# 期货研究情报助手

[English](README.md) | 简体中文

期货研究情报助手是一套面向研究工作的情报基础设施：把分散、非结构化的市场信息和机构研报整理成结构化、可追溯、按品种组织的研究视图。系统并不试图替代研究员的判断，也不会自动做交易决策；它负责完成证据的第一轮整理，只有在现有证据足够明确时，才形成方向性判断。

**核心原则：先有证据，再下结论。** 系统可以很有把握地识别一篇研报主要讨论哪个品种，但仍然没有足够证据将其计为偏多或偏空信号。这种克制是预期行为，不是系统失效。

### 快速体验有边界的实时 Demo

在仓库根目录创建项目虚拟环境并安装 `requirements.txt` 后运行：

```sh
NO_PROXY=htfc.com,www.htfc.com \
no_proxy=htfc.com,www.htfc.com \
PYTHONPATH=src .venv/bin/python3 -m futures_intelligence.main htfc-demo
```

Demo 最多处理 3 篇华泰期货研报，并全程使用确定性分析路径。它需要访问华泰期货官网，但不需要 OpenAI、API Key 或数据库。

### 桌面启动器

如果希望用简单的桌面窗口演示，可以在仓库根目录运行：

```sh
PYTHONPATH=src .venv/bin/python3 -m futures_intelligence.gui
```

打开后点击**运行 Demo**。桌面启动器需要访问华泰期货实时来源，但不需要 OpenAI API Key 或数据库；它与 `htfc-demo` 共用同一条确定性编排路径。命令行仍是排查问题和现场备用方式。在发布打包版本之前，本地 Python 需要包含 Tk 支持。

## 为什么做这个项目

期货研究员每天早晨往往要面对大量隔夜研报、公告、数据发布和市场更新。在真正开始判断之前，需要反复打开文件、识别相关合约、区分直接证据和背景提及，再按品种整理材料。

这个项目希望减少这些机械性的第一轮工作，让研究员把更多时间用在评估证据、检查假设和理解市场影响上，而不是把最终判断交给系统。

## 目前能做什么

- 采集并标准化来源材料，同时保留来源、原始链接、发布时间和提取过程等追溯信息。
- 支持有边界的 HTML 与文本层 PDF 研报处理，当前实时 Demo 已接入华泰期货研报路径。
- 从标题和正文中识别品种，并区分研报的**主要品种（Primary）**与仅被**提及的品种（Mentioned）**。
- 用可复核的确定性规则识别明确的市场变动和基本面事实。
- 对预期、条件、同一市场冲突、期限冲突和跨品种歧义采取保守处理。
- 识别价差和相对价值等结构性关系，但不会把它们直接转成偏多或偏空结论。
- 保存结构化的方向判定依据和品种级证据，再进行确定性的品种聚合与市场整体聚合。
- 输出有长度边界的报告依据和简洁的品种优先 Demo 简报。

当前[品种词库](knowledge/commodity_keywords.yaml)包含 19 个经过维护的品种身份，例如原油、燃料油、低硫燃料油、石油沥青、铜、铝、白银、黄金、铁矿石、豆粕、玉米、生猪、丙烯和乙二醇。这是一套实用但有限的覆盖，不代表已经覆盖中国期货市场的全部品种。

## 系统是怎么工作的

```text
信息来源
  ↓
采集器 / 抓取器 / 适配器
  ↓
MarketInformation 标准信息对象
  ↓
信息排序
  ↓
确定性报告分析
  ↓
品种相关性（Primary / Mentioned）
  ↓
品种聚合与市场整体聚合
  ↓
Demo 简报 / 早间情报层
```

这套架构原则上与来源无关。华泰期货只是当前已经实现的一条研报来源路径，并不是系统架构本身。后续可以在相同的采集和标准化边界下，逐步接入更多期货公司研报、交易所公告、官方统计、海关与库存数据、行情数据和新闻来源。

## 证据优先的分析方式

系统会把几个问题明确分开：

1. **研报在讨论什么？** 品种匹配会记录证据来自标题还是正文，以及命中的具体位置。Primary 的要求高于一般的上下文提及。
2. **研报有没有方向性证据？** 只有经过审阅的确定性信号才会形成方向。识别出品种本身不等于获得方向性证据。
3. **证据属于哪个品种？** 品种级证据可以避免把一个市场的陈述错误归到另一个品种上。
4. **证据是否应该进入聚合？** 结构化判定依据会区分直接证据、限定性表述、冲突、结构性背景和无方向信号。

当信息带有预期或条件、存在矛盾、跨越不同期限、只描述非方向性的结构关系，或者明确属于另一个品种时，系统会选择克制，而不是制造看似精确的结论。相对价值和价差信息只保留为结构性观察，不会被包装成交易建议。

## 一次真实 Demo

最终有边界的实时 Demo 成功处理了当期华泰期货研报，并因为标题明确识别出已跟踪品种而优先选择了：

> 华泰期货石油沥青专题20260904：供应端矛盾支撑市场强现实，预期仍存变数——结合华南沥青调研情况分析

系统将其识别为**主要品种 Bitumen（石油沥青）**，但确定性分析没有找到可进入方向聚合的证据：

```text
主要品种：                  Bitumen
报告方向：                  neutral
报告分析置信度：             80/100
判定依据：                  no_directional_signal

Bitumen 聚合方向：          neutral
聚合方向置信度：             0/100
报告数：                    1
```

这两个数字并不矛盾。`80/100` 是报告级确定性分析结果的置信度，其中包括对品种焦点的识别；它不表示“石油沥青中性方向有 80% 的概率”。聚合层的 `0/100` 表示这篇研报没有提供符合条件的偏多或偏空证据，因此没有方向性贡献。

这个例子展示的是“品种身份”和“市场方向”之间的保守分离。它不是对石油沥青的预测，也不代表石油沥青研报总会得到中性结论。

## 运行华泰期货 Demo

### 前置条件

- 支持标准虚拟环境的 Python 3
- 可以访问华泰期货官方网站的网络环境

在仓库根目录创建虚拟环境并安装仓库声明的依赖：

```sh
python3 -m venv .venv
.venv/bin/python3 -m pip install -r requirements.txt
```

Windows 用户可以使用仓库自带的安装脚本：

```bat
scripts\setup_windows.bat
```

从仓库根目录运行：

```sh
NO_PROXY=htfc.com,www.htfc.com \
no_proxy=htfc.com,www.htfc.com \
PYTHONPATH=src .venv/bin/python3 -m futures_intelligence.main htfc-demo
```

这条隔离的 Demo 路径具有以下边界：

- 最多选择 3 篇研报。
- 优先选择**标题**明确命中已跟踪品种的研报。
- 如果标题命中的研报不足 3 篇，再按现有顺序用最新的综合研报补足。
- 选样发生在 PDF 提取和分析之前，方向、置信度、判定依据和推理内容都不能影响选样成员或顺序。
- 报告详情按选样顺序展示，同时保留正常的信息排序用于分析处理。
- 使用确定性的规则分析器，不会构造或调用 LLM/OpenAI 路径。
- 不会调用生产早报服务，也不需要数据库持久化。

华泰期货来源在常规采集配置中仍然默认关闭；这条命令运行的是专门隔离、严格限量的 Demo 路径。

## 当前边界

- 品种覆盖经过人工维护，但并不全面；不同品种和规则族的语义覆盖深度也不相同。
- 方向规则是确定性且刻意保守的，许多研报会正确地保持中性或不参与方向聚合。
- `黑色专题` 这类宽泛板块标题，在没有明确品种证据时不会自动映射到具体期货合约。
- 当前华泰实时 Demo 最多选择 3 篇研报，不代表完整的每日研究信息池。
- 价差和相对价值等结构性表述不会被直接转换成交易建议。
- 项目定位是研究与信息基础设施，不是自动交易或下单系统。
- 系统不预测收益、不估算交易利润，也不提供投资建议。

## 后续方向

- 谨慎扩展经过审阅的品种身份覆盖。
- 在不削弱克制机制的前提下，增加确定性证据覆盖。
- 通过模块化适配器接入更多研报、官方数据、行情数据和新闻来源。
- 加强早间研究情报生成和证据追溯能力。
- 改进面向研究员的证据、判定依据和品种结论展示。

## 项目原则

- 先有证据，再下结论
- 保留来源和分析过程的追溯信息
- 宁可克制，也不制造虚假精度
- 将品种归属与方向性证据分开
- 保持聚合过程确定、透明、可检查
- 保持来源接入模块化且有明确边界
