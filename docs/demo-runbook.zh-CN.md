# 期货研究情报助手 — Demo 演示手册

[English](demo-runbook.md) | 简体中文

这份手册用于安全、清楚地演示有边界的华泰期货 Demo。README 回答“这是什么项目”，而这里回答“怎样把它讲清楚”：包括演示前检查、现场讲解顺序、常见问题和网络异常时的备用方案。

## 演示目标

演示结束时，希望观众理解三件事：

1. 系统可以把实时机构研报整理成结构化、按品种组织的研究情报。
2. 系统保留证据，并且把“研报属于哪个品种”和“研报有没有方向证据”分开处理。
3. 当证据不足时，系统会选择克制，而不是硬给偏多或偏空结论。

系统不是替研究员做判断，而是先完成采集、提取、品种识别、证据保留、确定性分析和品种聚合，把大量非结构化信息整理成值得研究的结构化视图。

## 30 秒开场

> 研究员每天要面对很多研报和市场更新，真正有价值的工作不是机械地打开 PDF、找品种、重新整理信息，而是后面的判断。这套系统先把这些材料整理成可追溯、按品种组织的研究视图，但不会替研究员做交易决策。它最重要的原则是：只有证据足够明确时才给方向，否则就明确保持克制。

## 3–5 分钟主流程

| 时间 | 操作 | 希望观众理解什么 |
| --- | --- | --- |
| 0:00–0:30 | 解释研究工作中的信息整理问题。 | 系统减少的是机械性的第一轮工作。 |
| 0:30–1:00 | 说明实时来源、三篇上限和分析前选样。 | 样本有边界，也不能按结果挑选。 |
| 1:00–2:30 | 运行命令，等待流程完成。 | 实时研报会变成结构化的确定性输出。 |
| 2:30–4:00 | 讲解第一篇品种明确的研报。 | 品种身份和方向证据是两件事。 |
| 4:00–5:00 | 讲解品种视图、广义研报和边界。 | 克制和可追溯本身就是可信度的一部分。 |

### 第一步 — 说明研究问题

> 研究员每天面对很多研报和市场信息，真正有价值的工作不是机械地打开 PDF、找品种、摘信息，而是后面的判断。这个系统想先把前面的整理工作自动完成，让研究员从一个结构化、可追溯的视图开始工作。

### 第二步 — 说明命令会做什么

> 这条命令会读取华泰期货的实时研报列表，最多选择 3 篇。标题明确命中已跟踪品种的研报优先，不足的部分再用更新的广义研报补足。选样发生在 PDF 提取和分析之前，所以方向、置信度、判定依据和推理内容都不能用来挑选一个“更好看”的结果。

实际顺序是：

```text
标题中的品种身份与发布时间
  → 选样
  → PDF 获取与提取
  → 信息排序
  → 确定性分析
  → 品种与市场整体聚合
  → 有边界的展示
```

分析过程中仍然保留正常的 `InformationRanker` 信息排序。报告详情则恢复为更早的选样/采集顺序，让观众看到分析前真正选中的样本顺序。

### 第三步 — 运行准确命令

在仓库根目录运行：

```sh
NO_PROXY=htfc.com,www.htfc.com \
no_proxy=htfc.com,www.htfc.com \
PYTHONPATH=src .venv/bin/python3 -m futures_intelligence.main htfc-demo
```

正常情况下会依次发生：

- 访问华泰期货实时研报列表。
- 选择不超过 3 篇研报。
- 获取并提取被选中的 PDF。
- 运行确定性的规则分析。
- 输出有长度边界的报告详情、品种视图、市场整体视图和简短 Demo Brief。

以下边界只针对 `htfc-demo`：它不会构造或调用 `LLMAnalyst`、不会创建 OpenAI 客户端、不会调用 `MorningBriefService`、不依赖数据库持久化，也不会写入交易订单或提供交易建议。

不要承诺固定时长，也不要承诺一定出现某几篇研报；这取决于当时的来源内容和网络情况。

### 第四步 — 第一眼看哪里

如果出现品种明确的研报，按这个顺序讲：

1. `主要品种`
2. `报告方向`
3. `报告分析置信度`
4. `判定依据`

之前已经通过验证的石油沥青案例是：

```text
主要品种：Bitumen
报告方向：中性 (neutral)
报告分析置信度：80/100
判定依据：no_directional_signal
```

建议这样解释：

> 这里最值得看的不是它有没有给偏多，而是它先正确识别出这篇报告主要研究 Bitumen，也就是石油沥青。然后它发现当前确定性规则下没有足够明确的方向证据，所以保持中性，没有硬给一个方向。

### 第五步 — 解释品种视图

接着指向：

```text
品种视图

Bitumen
方向：中性 (neutral)
聚合方向置信度：0/100
报告数：1
```

建议这样解释：

> 品种视图会把属于同一品种的报告证据放在一起。没有方向的报告仍然可以出现在品种视图里，但它不会被强行变成偏多或偏空贡献。在这次已经验证的案例中，系统纳入了 1 篇 Bitumen 研报；因为它没有提供符合条件的方向证据，所以聚合方向置信度保持为 0。

`报告数：1` 只对应这一次样本，不代表以后每次都应该是 1。

### 第六步 — 解释广义研报

之前的实时结果还包含一篇宏观政策研报和一篇黑色板块研报，作为补足样本。它们都被正常处理，但没有被强行赋予 Primary 品种。

> 这也是系统的保守边界。像 `黑色专题` 这样的宽泛标题，不会自动等同于铁矿石或煤炭等某个具体品种。没有明确的品种身份证据，系统就不猜。

## 怎样解释 80/100 和 0/100

如果观众注意到两个分数，可以直接这样说：

> 注意这里的 80 和下面的 0 不是一回事。`报告分析置信度 80/100` 不表示“石油沥青中性有 80% 的概率”，它表示系统对这篇报告的确定性分析结果有较高把握，其中包括明确识别出主要品种是 Bitumen。`聚合方向置信度 0/100` 表示这篇报告没有提供符合当前规则的偏多或偏空证据，所以对方向聚合没有贡献。这个结果不是系统没分析出来，而是它选择不硬给方向——这是一项可信边界，不是失败。

不要把任何一个分数解释成市场概率。

## 现场不要这样说

- “它在预测行情。”
- “系统认为沥青一定是中性。”
- “80 分就是 80% 概率。”
- “0 分说明分析失败。”
- “它可以替代研究员。”
- “它会自动给交易建议或下单。”
- “所有期货品种都覆盖了。”
- “它用 AI 把所有内容都读懂了。”

更准确的说法是：Demo 会整理研报证据、执行经过审阅的确定性规则，并在方向没有足够支持时明确保持克制。

## 常见问题与建议回答

### 为什么 Bitumen 报告分析置信度是 80，聚合方向置信度却是 0？

报告级分数反映系统对确定性分析结果的置信度，其中包括主要品种识别。聚合分数只考虑符合条件的方向贡献。这篇报告没有偏多或偏空证据进入聚合，所以方向贡献为零。

### 为什么系统有时会保持中性？

因为一篇研报可以明确属于某个品种，也可以提供背景信息、带条件的判断或互相冲突的表述，但仍不足以支持稳定的方向结论。这时保持中性或不参与方向聚合才是正确结果。

### 为什么黑色板块研报没有识别成具体品种？

`黑色专题` 是宽泛板块标签。没有明确的品种证据时，系统不会猜测这篇研报主要属于哪个具体合约。

### Demo 会使用 ChatGPT 或 OpenAI 吗？

这条有边界的 `htfc-demo` 路径是确定性的，不需要 OpenAI 或 API Key，也不会构造或调用 LLM 分析路径。仓库的其他部分可以包含其他分析组件；这里的结论只针对当前 Demo 命令。

### 为什么只处理 3 篇？

当前 Demo 刻意限制规模，让行为容易检查、复现和讲解。整个架构本身并不是只能处理 3 篇。

### 能否接入其他期货公司或数据源？

采集和标准化边界是模块化、与来源解耦的。其他机构研报、官方数据或行情数据都是自然的扩展方向，但没有完成和验证的接入不应在现场说成已经具备。

### 它能做交易决策吗？

不能。它负责整理研究证据并生成研究视图，不提供交易建议、不下单，也不替代研究员判断。

### 为什么这里用确定性规则，而不是 LLM？

确定性规则让证据边界更容易检查，行为更稳定，也更容易测试和阻止流畅但缺乏依据的结论。LLM 可以在其他层或未来工作中发挥作用，但这次 Demo 特意证明核心流程不依赖 LLM。这是针对当前有边界流程的选择，并不表示确定性规则在所有场景都更好。

## 实时输出可能变化

华泰期货的实时研报列表会变化，因此每次选中的报告可能不同，未来某一天也可能没有 Bitumen。判断 Demo 是否成功，应看流程是否按规则工作，而不是看某个写死的标题是否出现。

如果当天没有任何已跟踪品种明确出现在标题中，系统可能合理地选择广义研报作为回退，最终也可能得到 0 个品种视图。可以这样解释：

> 今天当前 listing 里没有标题明确命中我们已跟踪品种的报告，所以系统按规则回退到更新的广义研报。它没有根据宽泛标题去猜一个品种归属。

不要为了得到更“好看”的结果反复重跑。

## 失败与回退手册

| 情况 | 应该怎么做 | 不要怎么做 |
| --- | --- | --- |
| 命令成功，但选中的研报与上次不同。 | 正常继续，并说明实时 listing 会变化。 | 不要声称每次都应该出现石油沥青案例。 |
| 命令成功，但品种视图为 0。 | 解释保守回退和当前经过维护但有限的品种覆盖。 | 不要反复运行，试图碰到一个更漂亮的结果。 |
| 华泰超时或暂时不可用。 | 明确说明来源端点暂时不可用，随后切换到下方已验证的历史输出。 | 不要现场改代码、增加超时时间，也不要暗示本次命令成功了。 |
| Python 或依赖启动失败。 | 检查命令使用的是 `.venv/bin/python3`，并确认仓库本地虚拟环境存在。 | 不要把 Demo 命令换成系统 `python3`。 |
| 出现意外 traceback。 | 停止本次实时执行，改用已验证的输出继续讲解流程。 | 不要在观众面前临时修改代码。 |

## 20 秒收尾

> 所以现在这套系统完成的不是替研究员下结论，而是把每天大量研报先整理成可追溯的品种视图，并明确告诉我们哪里有方向证据、哪里没有。下一步最有价值的方向，是继续扩充经过审阅的品种和证据覆盖、接入更多可靠来源，再把这些结果更紧密地接到早间研究流程里。
